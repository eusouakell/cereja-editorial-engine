# Format library

A format is a **channel-aware composition contract**. It defines the minimum inputs, structure, constraints and review criteria required to turn an Editorial Packet into a publication.

The newsletter is the richest recurring publication, but it is not the only canonical object. Channel outputs should be composed from the same approved packet rather than mechanically summarized from one another.

Initial formats:

- [Newsletter — quinzenal Cereja](newsletter/quinzenal-cereja.md)
- [LinkedIn — metapost](linkedin/metapost.md)
- [Instagram — revista visual](instagram/revista-visual.md)
- [Stories — research desk](stories/research-desk.md)
- [Medium — durable essay](medium/essay.md) — **PILOT**
- [DEV.to — technical / build article](devto/technical-article.md) — **PILOT**
- [YouTube — spoken explainer / demonstration](youtube/video.md) — **PILOT**

## Production specs

Editorial format contracts answer **what the channel piece should do**.

[Channel production specs](production/README.md) answer **how the final asset must be delivered**: dimensions, aspect ratio, safe area, file type, export constraints, technical accessibility prerequisites and volatile platform checks.

The two layers are intentionally separate. Flame remains the source of brand truth.

New formats should be added only after a real publishing need appears. Medium, DEV.to and YouTube are time-bounded pilots under [Marketing Plan V3](../growth/company-marketing-plan-v3.md); their presence here is not a commitment to permanent cadence.
